# Acoustic piano corpus preparation — aligned MIDI ground truth

Tracking: [#119](https://github.com/shafranek-js/Nota-Re/issues/119), parent [#82](https://github.com/shafranek-js/Nota-Re/issues/82). This is **offline experiment tooling**, not acoustic-piano input for live lessons.

The benchmark must compare detected note attacks against an **independent reference**. The reference must not be generated by PitchPlease, Basic Pitch or another candidate detector.

## MIDI to note-on ground truth

`scripts/maestro-midi-onsets.mjs` reads Standard MIDI Files format 0/1 using positive PPQ time, running status, all tracks and global tempo changes. It reports physical MIDI Note On events, excluding Note Off (including velocity-zero events) and sustain/controller messages. It deliberately does **not** infer acoustic damping or releases.

`scripts/create-piano-reference-case.mjs` reads the independently aligned MIDI recording and one corresponding WAV clip, verifies its duration, selects MIDI note attacks in the same time window and rebases timestamps to the start of the WAV clip.

The audio/MIDI pair should be synchronized by the dataset or an external recording setup. **A matching filename is not proof of alignment**. Residual acoustic delay, digital recording latency and the per-take clock offset must be calibrated separately before using onset error or timing results.

Example for an aligned recording with a 10 s start and 8 s duration:

```sh
ffmpeg -i full-piano.wav -ss 10 -t 8 -ac 1 -c:a pcm_s16le piano-clip.wav
node scripts/create-piano-reference-case.mjs full-piano.mid piano-clip.wav 10000 8000 piano-take-1 chord > case.json
```

The resulting `case.json` has:

```json
{
  "id": "piano-take-1",
  "category": "chord",
  "wav": "piano-clip.wav",
  "expected": [
    { "midi": 60, "onsetMs": 123.4 },
    { "midi": 64, "onsetMs": 123.4 }
  ]
}
```

Those timestamps are **illustrative**, not real piano results. Combine case objects inside a local `manifest.json`:

```json
{
  "schemaVersion": 1,
  "onsetToleranceMs": 100,
  "cases": []
}
```

Replace the empty `cases` array with your cases. WAV paths are resolved relative to the manifest's directory. For the first PitchPlease comparison:

```sh
node --experimental-strip-types scripts/export-pitchplease-onsets.mjs manifest.json > detected.json
node --experimental-strip-types scripts/evaluate-piano-detector.mjs detected.json
```

PitchPlease must first be installed separately at exact version 3.1.0 as described in [MICROPHONE_PITCHPLEASE_OFFLINE.md](MICROPHONE_PITCHPLEASE_OFFLINE.md). Neither benchmark tool is bundled into the production web app.

## Corpus quality and safety

- Begin with recordings that have **independently recorded aligned MIDI**, such as MAESTRO piano performances, then add acoustically recorded examples with manually validated attack times. Do not invent reference timestamps.
- Confirm whether the MIDI timestamps represent key press, recorded digital onset or another event origin. A quiet hammer attack may reach the microphone later than the physical switch.
- Record piano/device, mic placement, room, sample rate, gain processing, sustain pedal, reference A4 and synchronization method.
- Split recordings by performance/piano/setup before tuning thresholds, not by neighboring clips of the same take.
- Test genuine octave dyads separately from false octave harmonics, repeated notes with sustain and incomplete chords.
- Do **not** upload microphone recordings or bundle MAESTRO audio into Nota-Re. Respect MAESTRO's noncommercial CC BY-NC-SA terms and all other corpus licenses.
- The included tests use fabricated MIDI bytes and are **parser unit tests**, not music recognition accuracy evidence.

## Explicit limitations

The parser rejects SMPTE timing, MIDI format 2 and nonstandard/truncated MIDI files; convert them to regular aligned SMF format 0/1 first. The WAV decoder supports RIFF PCM16/24/32 and float32, but not every extensible WAV variant. The clipping tool assumes independent source alignment and a matching WAV duration; it cannot recover a missing recording offset or diagnose an out-of-sync corpus automatically.

A successful MIDI parser test does not validate microphone onset timestamps, release behavior, multi-pitch performance, or whether a lesson can be certified.
